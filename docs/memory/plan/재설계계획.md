# 재설계 계획 — 4계층 메모리

본 계획은 사용자 철학(T1 주요한 사실 / T2 구체적 정보 / T3 탐색 능력 / T4 추론)을
코드 레벨에 명시하는 가장 작은 변경 묶음을 정의한다.
파괴적 변경을 피하고, 기존 디스크 레이아웃과 호환을 유지한다.

## 목표

1. T1을 코드의 1급 시민으로 만든다 — “critical fact”가 있으면 *어떤 쿼리에도* 무관하게 system prompt에 들어간다.
2. 자동 promote 경로를 정비한다 — 인사이트의 importance에 따라 critical 자리로 자동 흘러간다.
3. 검색의 회수율을 끌어올린다 — 다국어/벡터/요약 매칭을 결합해 T2 회수가 더 자주 잡히게.
4. 페르소나 프롬프트가 메모리 사용을 능동적으로 명령한다 — T3 활용 빈도 상승.
5. 회수 결과를 **관측 가능**하게 만든다 — 무엇이 들어갔고 무엇이 빠졌는지 이벤트로 노출.

비목표:
- legacy `SessionMemoryManager` 코어 재작성 (그대로 둔다)
- v0.20.0 Provider 브리지 본체 재구현 (이전 감사의 GP1만 별도 PR로 픽스)
- 임베딩 모델 교체

## 4계층 구조

```
┌──────────────────────────────────────────────────────────┐
│ T1 — Critical Facts (always-pinned)                      │
│   memory/critical/*.md  +  MEMORY.md                     │
│   매 턴 system prompt에 무조건 주입 (budget의 30%)        │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ T2 — Specific Notes (search-on-demand)                   │
│   memory/{conversations,dms,daily-journal,topics,        │
│            projects,insights,compactions,daily}/*.md     │
│   GenyMemoryRetriever L3-L6 (벡터 + 키워드 + 백링크 + 큐레이티드)│
│   + agent의 memory_search/memory_read 툴                 │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ T3 — Index/Map (always-pinned, 약 500자)                  │
│   memory/_vault_map.json (이미 존재)                      │
│   매 턴 system prompt 꼬리에 “목차”로 박힘                │
│   에이전트가 “저기 뭐가 있구나” 파악 → memory_search 동기  │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ T4 — Working/STM (recent_turns)                          │
│   transcripts/session.jsonl                              │
│   GenyMemoryRetriever L0 (기본 6턴)                       │
└──────────────────────────────────────────────────────────┘
```

### 단계 1 — T1 계층 도입

**P1.1.** `memory/critical/` 카테고리를 화이트리스트에 추가.
파일: `Geny/backend/service/memory/structured_writer.py`
변경: `VALID_CATEGORIES`에 `"critical"` 추가.

**P1.2.** `LongTermMemory.load_critical_pinned()` 추가.
파일: `Geny/backend/service/memory/long_term.py`
변경: 새 메서드 — `memory/critical/*.md` 모두 + `MEMORY.md` body를 읽어 합쳐서 반환.
시그니처: `load_critical_pinned(self, max_chars: int = 3000) -> Optional[MemoryEntry]`
반환: 단일 `MemoryEntry`로 카테고리 “critical”, 본문에 모든 critical 노트가 합쳐짐. 빈 경우 None.

**P1.3.** `GenyMemoryRetriever`에 새 레이어 “L1.6 critical facts” 삽입.
파일: `geny-executor/src/geny_executor/memory/retriever.py`
변경: `_load_session_summary` 직후, `slim_mode` 분기 전에 다음을 호출.
```python
total_chars = self._load_critical_pinned(chunks, total_chars, budget)
```
함수 본문:
```python
def _load_critical_pinned(self, chunks, total, budget):
    try:
        ltm = getattr(self._mgr, "long_term", None)
        if ltm is None: return total
        loader = getattr(ltm, "load_critical_pinned", None)
        if loader is None: return total
        max_pin = int(budget * 0.30)  # critical은 30% budget
        pinned = loader(max_chars=max_pin)
        if not pinned or not pinned.content: return total
        chunks.append(MemoryChunk(
            key="critical_pinned",
            content=pinned.content,
            source="critical",
            relevance_score=2.0,
            metadata={"layer": "critical_pinned"},
        ))
        return total + pinned.char_count
    except Exception:
        logger.debug("retriever: critical_pinned load failed", exc_info=True)
        return total
```
보장: 매 턴 critical 디렉토리/파일이 *쿼리 무관* 주입.

**P1.4.** `MemoryContextBlock`이 critical을 다른 섹션으로 분리해 노출.
파일: `geny-executor/src/geny_executor/stages/s03_system/artifact/default/builders.py:81-92`
변경:
```python
def render(self, state: PipelineState) -> str:
    parts = []
    pinned = state.metadata.get("memory_pinned", "")
    if pinned:
        parts.append(f"# Pinned Facts\n{pinned}")
    ctx = state.metadata.get("memory_context", "")
    if ctx:
        parts.append(f"# Relevant Knowledge\n{ctx}")
    return "\n\n".join(parts)
```
Stage 02도 critical 청크를 분리해 `state.metadata["memory_pinned"]`에 따로 박는다.

### 단계 2 — 자동 promote 경로

**P2.1.** `GenyMemoryStrategy._save_insights`가 importance ∈ {critical, high}일 때 critical 디렉토리에도 동시 기록.
파일: `geny-executor/src/geny_executor/memory/strategy.py:435-446`
변경: 기존 `curated.write_note(...)` 분기에 더해
```python
if importance in ("critical", "high"):
    try:
        write_note = getattr(self._mgr, "write_note", None)
        if write_note:
            write_note(
                title=item.get("title", "Insight"),
                content=item.get("content", ""),
                category="critical",
                tags=item.get("tags", []) + ["pinned"],
                importance=importance,
                source="auto_pinned",
            )
    except Exception:
        logger.debug("strategy: critical pin failed", exc_info=True)
```

**P2.2.** 에이전트 노출 툴 `memory_pin` 추가.
파일: `Geny/backend/tools/built_in/memory_tools.py`
시그니처: `memory_pin(session_id, title, content, tags=[], source="agent")` → critical 카테고리로 강제 저장.
의도: LLM이 “이건 영구 기억해야 함” 판단했을 때 명시적으로 부를 수 있게.

**P2.3.** UI / 인스펙터에서 critical 디렉토리를 **상단**에 노출.
파일: 필요 시 `Geny/backend/controller/memory_controller.py` 응답 정렬 변경.

### 단계 3 — T3(목차) 항상 주입

**P3.1.** retriever에 “vault_map_lite” 레이어를 추가하되 *slim_mode와 무관하게 항상 작동*.
파일: `geny-executor/src/geny_executor/memory/retriever.py:271-303`
변경: `_load_vault_map`을 `_load_critical_pinned` 직후 무조건 호출 (단, slim_mode이면 깊이 더 보고, 풀 모드여도 짧은 인덱스만 박음).

목적: 에이전트가 “memory에 무엇이 있을 수 있는지” 항상 보게 된다 → memory_search 동기.

## 변경 영향 요약

| 영역 | 영향 |
|---|---|
| 디스크 레이아웃 | `memory/critical/*.md` 추가만, 기존 카테고리 그대로 |
| 인덱스 | `_index.json`은 기존 스키마 + critical 카테고리, 기존 코드 호환 |
| 시스템 프롬프트 길이 | budget의 30% 추가 점유, max_inject_chars 자체는 유지 |
| 검색 비용 | critical 디렉토리 추가 로드만, 큰 비용 없음 |
| 호환성 | 새 retriever 레이어는 try/except로 감싸 기존 manager에서 method 부재 시 silent skip |
| Phase 5/6/7(executor v0.20.0 브리지) | 별개 트랙, 본 PR과 충돌 없음 |

## 검증 시나리오

1. **새 세션 + 임의 한국어 질의** — `memory/critical/`에 “주인님” 노트가 있으면 system prompt `Pinned Facts`에 그 본문이 등장. retrieve breakdown 이벤트로 확인.
2. **빈 critical 디렉토리** — 기존 동작과 동일(메모리 섹션 비거나 vault_map_lite만).
3. **importance=critical 인사이트 새로 저장** — `auto_pinned` 태그로 critical/에도 동시 저장됨을 확인.
4. **임베딩 키 부재 + 한국어 질의** — vault_map_lite가 항상 있으므로 LLM이 메타 정보 보고 `memory_search`를 호출 → 키워드 normalize 후 critical 키워드 매칭 시 본문 반환.
5. **`memory_pin` 툴** — LLM이 부르면 critical/<slug>.md 생성, 다음 턴에 즉시 주입.

## 비목표 / 후속 검토

- 임베딩 모델 다국어 강화(예: multilingual-e5)는 별도 트랙.
- vault graph(`linked_from` 깊이 탐색)는 백링크 1홉 한정 유지.
- T1 자동 expiration(예: “30일 안 부르면 demote”) — 후속 검토 항목.
- v0.20.0 provider 측 critical 계층 매핑 — Provider Protocol에 `pinned()` 추가 검토(나중).
