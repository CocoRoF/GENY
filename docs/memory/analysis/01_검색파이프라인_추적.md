# 01 · 검색 파이프라인 코드 라인 추적

매 턴 메모리가 system prompt까지 흘러가는 경로를 코드 라인 단위로 따라간다.
모든 인용은 `geny-executor` 와 `Geny` 의 실제 파일이다(주석 아님).

## 전체 흐름도

```
[사용자 입력]
   │
   ▼
Stage 02 ContextStage.execute()             geny-executor/.../s02_context/.../stage.py:174
   │
   ├─→ retriever.retrieve(query, state)      ← GenyMemoryRetriever
   │
   └─→ provider.retrieve(RetrievalQuery)     ← (선택) 새 Provider 경로
   │
   ▼
state.metadata["memory_context"] = "<요약 텍스트>"   stage.py:207
   │
   ▼
Stage 03 SystemStage가 ComposablePromptBuilder로 system prompt 조립
   │
   ├─→ PersonaBlock         (페르소나)
   ├─→ DateTimeBlock        (현재 시각)
   └─→ MemoryContextBlock.render(state)         builders.py:88
        │
        └─→ state.metadata.get("memory_context", "")
            └─→ 비어있으면 "" 반환 (즉 system prompt에 메모리 블록 통째로 사라짐)
```

## Stage 02 ContextStage 상세

`geny-executor/src/geny_executor/stages/s02_context/artifact/default/stage.py:174-207`

```python
chunks = list(await self._retriever.retrieve(str(query), state))
# ...
if chunks:
    # ...
    memory_text = "\n".join(f"- [{c.source}] {c.key}: {c.content}" for c in chunks)
    if state.messages and state.iteration == 0:
        state.metadata["memory_context"] = memory_text
```

핵심: `chunks`가 비면 `memory_context`는 **설정조차 되지 않는다**. `MemoryContextBlock`은 빈 문자열을 반환한다. 결과적으로 system prompt에는 메모리 섹션이 통째로 없다.

## GenyMemoryRetriever 6계층

`geny-executor/src/geny_executor/memory/retriever.py:98-165`

```python
async def retrieve(self, query: str, state: PipelineState) -> List[MemoryChunk]:
    if not self._mgr or not query.strip():
        return []
    search_query = query[: self._search_chars].strip()
    # LLM 게이트: 옵션, 패스
    chunks: List[MemoryChunk] = []
    total_chars = 0
    budget = self._max_inject

    # 0. 최근 STM 턴
    if self._recent_turns > 0:
        total_chars = self._load_recent_turns(chunks, total_chars, budget)
    # 1. 세션 요약
    total_chars = self._load_session_summary(chunks, total_chars, budget)
    if self._slim_mode:                                                      # 기본 False
        total_chars = self._load_vault_map(chunks, total_chars, budget)
        return chunks
    # 2. MEMORY.md (메인 LTM)
    total_chars = self._load_main_memory(chunks, total_chars, budget)
    # 3. 벡터 검색
    if self._enable_vector:
        total_chars = await self._load_vector_memory(chunks, search_query, total_chars, budget)
    # 4. 키워드 검색 + importance boost
    total_chars = self._load_keyword_memory(chunks, search_query, total_chars, budget)
    # 5. 백링크 컨텍스트
    total_chars = self._load_backlink_context(chunks, total_chars, budget)
    # 6. 큐레이티드 지식
    if self._curated:
        total_chars = self._load_curated_knowledge(chunks, search_query, total_chars, budget)
    return chunks
```

각 계층의 *조건*은 다음과 같다.

| 레이어 | 어떤 데이터를 보는가 | 새 세션에서 결과 |
|---|---|---|
| L0 recent_turns | `mgr.short_term.get_recent(n)` | **빈 리스트**(새 세션은 STM 비어있음) |
| L1 session_summary | `mgr.short_term.get_summary()` | **None**(아직 요약 안 만들어짐) |
| L1.5 vault_map | slim_mode일 때만 | 기본 `slim_mode=False`라 **건너뜀** |
| L2 MEMORY.md | `mgr.long_term.load_main()` | 사용자가 직접 채우지 않으면 **빈 파일/없음** |
| L3 vector | `mgr.vector_memory.search(q)` | 임베딩 키 없으면 **disabled**, 있어도 의미 매칭 |
| L4 keyword | `mgr.search(q)` → `_ltm.search(q)` | 키워드가 안 맞으면 **0건** |
| L5 backlink | L0~L4가 뭔가 가져와야 작동 | 위에서 0건이면 **0건** |
| L6 curated | `curated_km.inject_context(q, ...)` | curated 매니저 없으면 **건너뜀** |

L4의 동작은 다음 문서(`02`)에서 라인 단위로 본다.

## Geny 측 Pipeline 부착 라인

`Geny/backend/service/executor/agent_session.py:1746-1756` (기본 빌드 경로)

```python
retriever_kwargs: Dict[str, Any] = dict(
    max_inject_chars=max_inject_chars,
    enable_vector_search=_tuning["enable_vector_search"],
    curated_knowledge_manager=curated_km,
    recent_turns=_tuning["recent_turns"],
)
if _tuning.get("slim_mode"):
    retriever_kwargs["slim_mode"] = True
attach_kwargs["memory_retriever"] = GenyMemoryRetriever(
    self._memory_manager, **retriever_kwargs,
)
```

확인 사실:
- `slim_mode`는 settings.json `memory.tuning.slim_mode`가 true일 때만 활성화. 기본 false.
- `_tuning["recent_turns"]` 기본 6 (`Geny/backend/service/memory_provider/config.py:153`).
- `enable_vector_search` 기본 True지만 실제 작동하려면 `LTM_EMBEDDING_API_KEY`가 있어야 한다(`vector_memory.py`).
- `curated_knowledge_manager`는 사용자에 묶인 별도 매니저로, 인스턴스 자체가 None일 수 있다.

## Provider 경로(이중 경로)

`stage.py:178-186`

```python
if self._provider is not None and query:
    rq = RetrievalQuery(text=str(query))
    result = await self._provider.retrieve(rq)
    seen_keys = {c.key for c in chunks}
    for c in result.chunks:
        if c.key not in seen_keys:
            chunks.append(c)
```

즉 새 `MemoryProvider`도 결과를 합치게 되어 있다. 하지만:
- Geny 쪽 `MemorySessionRegistry.provision()`이 깨져 있어(이전 감사 GP1) provider 자체가 attach되지 않는다.
- 설령 attach 되더라도 같은 디스크를 보고 키워드 검색을 돌리므로 결과는 같다.

## MemoryContextBlock 라인

`geny-executor/src/geny_executor/stages/s03_system/artifact/default/builders.py:81-92`

```python
class MemoryContextBlock(PromptBlock):
    @property
    def name(self) -> str:
        return "memory_context"

    def render(self, state: PipelineState) -> str:
        memory_ctx = state.metadata.get("memory_context", "")
        if not memory_ctx:
            return ""
        return f"# Relevant Knowledge\n{memory_ctx}"
```

비면 `""` — system prompt에 빈 줄조차 없다.

## 정리

이 파일은 “메모리는 어디서 system prompt로 가는가”의 답이다.
한 줄로: **`Stage 02`가 `chunks`를 못 모으면, `MemoryContextBlock`은 빈 문자열이고, system prompt에는 메모리 자체가 등장하지 않는다.**
