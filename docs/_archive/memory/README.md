# Geny/docs/memory — 메모리 서브시스템 재감사

작성일: 2026-05-03
대상 레포: `geny-executor`, `geny-executor-web`, `Geny`
이전 감사: `~/geny-memory-docs/` (참고만, 본 문서가 우선)

## 왜 다시 작성하는가

이전 감사는 코드 구조에 갇혀 있었다. 사용자가 실제로 보고 있는 실패 사례
(`insights/User prefers to be addressed as 주인님` 가 디스크에 존재함에도
에이전트가 “처음 뵙는 것 같은데”라고 응답)는 *왜 일어나는가*에 대한 질문이다.
정답은 “파일이 있다 / 없다”가 아니라 “인젝션 파이프라인의 어느 계층이 부재한가”이다.

본 문서는 사용자 철학을 1차 기준으로 삼아 코드를 다시 읽는다.

## 사용자 철학(이번 감사의 평가축)

1. **주요한 사실**은 반드시 기억해야 한다 — 매 턴 system prompt에 *무조건* 들어가야 하는 정보.
2. **구체적 정보**는 markdown으로 LTM 정보 저장소에 저장된다 — 디스크에 그대로.
3. 에이전트는 환경 속 정보를 *탐색하는 능력*을 갖춘다 — `memory_search`/`memory_read` 같은 툴.
4. 그 외 나머지는 LLM이 추론으로 해결한다.

이 4단계 중 **(1)이 현 아키텍처에 명시적으로 존재하지 않는다.** 그게 본 감사의 핵심 결론이다.

## 핵심 결론(한 줄 요약)

> **현재 메모리 시스템은 “구체적 정보 + 탐색 능력” 두 계층만 구현되어 있고
