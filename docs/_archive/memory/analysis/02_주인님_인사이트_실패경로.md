# 02 · “주인님” 인사이트가 절대 못 나오는 이유 (라인 단위)

대상: `memory/insights/User prefers to be addressed as 주인님.md`
질의 텍스트: 사용자가 직전에 던진 첫 메시지(스크린샷에선 `"뭐하고 있었어"`)
기대 결과: 위 인사이트 본문이 system prompt `<memory>` 또는 `# Relevant Knowledge` 섹션에 포함됨
실제 결과: 빈 문자열 → 에이전트 “처음 뵙는 것 같은데”

## 6계층 한 단계씩 통과 시뮬레이션

`GenyMemoryRetriever`의 6계층(`geny-executor/src/geny_executor/memory/retriever.py`)을 새 세션 + 위 질의 기준으로 추적.

### L0 — recent_turns (`retriever.py:169-244`)

```python
recent = get_recent(self._recent_turns)        # 기본 6
if not recent:
    return total
```

새 세션 STM은 비어있다 → `recent = []` → 종료. **0 chunk.**

### L1 — session_summary (`retriever.py:248-267`)

```python
summary = stm.get_summary()                    # transcripts/summary.md
if summary and ...
```

새 세션의 `transcripts/summary.md`는 없거나 비어있다(`stm.get_summary()` → None / ""). **0 chunk.**

### L1.5 — vault_map (`retriever.py:271-303`)

`slim_mode=False`(기본)이면 이 분기 자체에 들어오지 않는다. settings.json에 `memory.tuning.slim_mode=true`를 켜야 활성. **본 케이스에서는 0 chunk.**

(켰을 때조차 `index_manager.render_vault_map()`은 “목차”만 주입하므로 인사이트 본문은 안 들어간다.)

### L2 — MEMORY.md (`retriever.py:307-329`)

```python
main_mem = ltm.load_main()                     # memory/MEMORY.md
if main_mem and main_mem.content and ...
```

`MEMORY.md`는 “evergreen” 파일이다. **insights 카테고리는 `MEMORY.md`로 자동 합쳐지지 않는다** — Geny의 `StructuredMemoryWriter.write_note()`는 `insights/<slug>.md` 단일 파일로 떨어뜨리고 끝이다(`Geny/backend/service/memory/structured_writer.py`).

따라서 `MEMORY.md`가 비어있으면(보통 비어있음) **0 chunk.** 사용자가 명시적으로 `memory_write_main` 류 툴을 부르거나 직접 `MEMORY.md`에 쓰지 않으면 영원히 비어있다.

### L3 — vector search (`retriever.py:333-374`)

```python
vmm = getattr(self._mgr, "vector_memory", None)
if vmm is None or not getattr(vmm, "enabled", False):
    return total
v_results = await vmm.search(query, top_k=self._max_results)
```

조건 1: `LTM_EMBEDDING_API_KEY` 환경변수 또는 settings.json에 임베딩 키가 있어야 한다(`Geny/backend/service/memory/vector_memory.py:initialize`).
조건 2: 인덱스가 빌드되어 있어야 한다(`mgr.initialize_vector_memory()` 호출).

설령 활성화되어 있어도:
- 쿼리: `"뭐하고 있었어"` (한국어 일상어)
- 인덱싱된 인사이트 청크 본문: `"User requested to be called '주인님' (master/owner) in Korean. This is a stated user preference for how the agent should address them."` (영어 위주)

`text-embedding-3-small`(기본) 다국어 성능이 좋다 해도 두 문장은 **의미적으로도 별개의 주제**(현재 행동 질문 vs 호칭 선호). 코사인 유사도가 `score_threshold=0.35`(기본)을 넘기 어렵다.

판정: 가능성은 있으나 **신뢰할 수 없음.** 본 케이스에서는 결과 0건이라 가정해도 무리 없다.

### L4 — keyword search (`retriever.py:378-442` → `manager.search` → `long_term.search`)

`Geny/backend/service/memory/long_term.py:407-451`

```python
entries = self.load_all()
query_lower = query.lower()
keywords = [w for w in query_lower.split() if len(w) >= 2]   # ← 핵심
if not keywords:
    return []

for entry in entries:
    content_lower = entry.content.lower()
    hits = sum(content_lower.count(kw) for kw in keywords)
    if hits == 0:
        continue
    # ... density × 0.7 + recency × 0.3
```

질의 분해:
- `"뭐하고 있었어".lower().split()` → `["뭐하고", "있었어"]` (각각 한국어 음절 3, 3 → `len() >= 2` 통과)

인사이트 본문(소문자):
```
user requested to be called '주인님' (master/owner) in korean. this is a stated user preference for how the agent should address them.
```

`"뭐하고"` `count → 0`, `"있었어"` `count → 0` ⇒ `hits == 0` ⇒ `continue`.

그리고 검색 함수는 `MemoryEntry` 단위로 도는데, **인사이트 파일(`memory/insights/...`)이 `entries`에 들어 오는지부터** 확인해야 한다. `_list_md_files()`는 `memory/`의 모든 `.md` 파일을 스캔하므로 들어오긴 한다. 그러나 keyword가 안 맞아 fallthrough.

판정: **0건. 본 실패의 결정적 원인.**

### L5 — backlink (`retriever.py:446-496`)

L0~L4가 chunk를 모은 게 있어야 그 노트의 `links_to`를 따라간다. 위에서 0건이므로 **0 chunk.**

### L6 — curated (`retriever.py:500-526`)

```python
if self._curated is None: return total
ck_text = self._curated.inject_context(query, max_chars=remaining)
```

Geny에서 `curated_km`은 사용자별 `CuratedKnowledgeManager`. 본 케이스 사용자에 큐레이티드가 묶여있는지 모르지만, 묶여있어도 같은 키워드 검색을 돌릴 가능성이 높아 결과는 똑같다(`curated_knowledge.py:inject_context`).

## 본질

이 실패는 *버그가 아니다*. 검색 기반 인젝션의 **아키텍처적 한계**다.

- 모든 메모리 회수가 **질의 텍스트와의 어휘 일치**에 묶여 있다.
- 사용자가 “당신의 호칭 선호”와 무관한 질의를 하면, 호칭 정보는 어떤 방식으로도 들어가지 않는다.
- 즉 “주요한 사실”은 검색 운빨에 맡겨진 상태다 — 사용자 철학과 정면 충돌.
