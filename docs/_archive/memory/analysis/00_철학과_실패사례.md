# 00 · 사용자 철학과 관찰된 실패 사례

## 사용자가 명시한 메모리 철학

> 주요한 사실은 반드시 기억해야 하는 것들이고
> 구체적 정보는 markdown으로 정보 저장소에 저장되고 (LTM)
> Agent는 이러한 정보를 탐색하는 "환경 속 탐색" 능력을 갖추고 있는 상태고
> 나머지를 파악하는 방식

이 문장을 4계층 모델로 해체하면 다음과 같다.

| 계층 | 이름 | 정의 | 주입 방식 |
|---|---|---|---|
| **T1** | 주요한 사실 | 매 턴 반드시 알아야 하는 것 (예: 사용자가 “주인님”이라 불러달라고 한 것) | system prompt에 **무조건** 포함 |
| **T2** | 구체적 정보 | 깊이 있는 사실, 회의록, 노트, 대화 로그 | `memory/**/*.md`로 저장 |
| **T3** | 탐색 능력 | T2를 찾아오는 도구 | `memory_search` / `memory_read` 등 툴 호출 |
| **T4** | 추론 | LLM이 직접 판단 | 프롬프트만으로 처리 |

T1과 T2는 의도가 다르다. T1은 “저장 + 항상 주입”이고 T2는 “저장 + 필요 시 검색”이다.
**현 아키텍처는 T1을 표현할 수 없다.**

## 관찰된 실패 사례

스크린샷에 찍힌 디스크 상태:
```
memory/
├── conversations/        285개
├── dms/                    3개
├── daily-journal/          3개  (Day journal — 2026-05-01/02/03)
├── insights/               4개
│   ├── User appreciates thoughtful, ...
│   ├── User prefers to be addressed as 주인님   ← 본 케이스
│   ├── User assigned agent name: ...
│   └── User enjoys build crafting in ...
└── topics/                 8개
```

선택된 인사이트 본문:
```
제목: User prefers to be addressed as 주인님
태그: #communication_preference #korean
중요도: high (■ 표시)
본문: User requested to be called '주인님' (master/owner) in Korean.
      This is a stated user preference for how the agent should address them.
```

대화 로그(스크린샷의 화면 텍스트):
```
[에이전트] 아, 왔군요 😊 처음 뵙는 것 같은데, 어떻게 불러드리면 될까요?
[사용자]   뭔소리야 어떻게 부르는지 기억 안 나?
[에이전트] 아, 맞아요 — 솔직히 말하면 저 아직 여기 온 지 얼마 안 됐어서,
           이전에 나눈 대화가 잘 안 잡혀요 😅
           ...
           대화를 나눈 기억이 별로 없어서 그렇게 말했어요.
```

즉, **인사이트는 디스크에 존재하지만 에이전트는 그것을 인지하지 못했다.**

## 이 사례가 보여주는 것

1. 저장(write) 경로는 정상이다 — `memory_distill` / `StructuredMemoryWriter`가 인사이트를 `insights/` 카테고리로 정확히 떨어뜨렸다.
2. 추출(retrieve) 경로 어딘가가 망가졌다 — 매 턴 system prompt에 들어가야 할 정보가 안 들어갔다.
3. 에이전트의 “탐색 능력”도 발동되지 않았다 — `memory_search` 툴을 부르지 않았거나, 부르더라도 못 찾았다.
