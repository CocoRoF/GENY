# 메모리 서브시스템 평가 보고서

작성일: 2026-05-03
대상: `geny-executor` v0.20.0, `geny-executor-web`, `Geny`(레거시 + v0.20.0 브리지)
근거: 본 폴더 `analysis/00 ~ 06.md`(코드 라인 인용)
이전 감사: `~/geny-memory-docs/`(구조 분석에 한정, 본 보고서가 우선)

## 한 줄 평가

**현재 메모리 시스템은 “저장한다”는 약속은 지키지만 “기억한다”는 약속은 지키지 못한다.**

저장 경로(write)는 안정적으로 디스크에 정보를 떨어뜨리고 인덱스를 갱신한다. 그러나 회수 경로(retrieve)는 **사용자의 어휘가 인사이트의 어휘와 일치할 때**에만 그 정보를 system prompt까지 운반한다. 일치하지 않으면 — 새 세션이거나 한국어/영어가 섞이거나 주제가 다르면 — 디스크에 있는 사실은 영원히 모델 시야 밖에 있다.

스크린샷의 “주인님” 사례는 우연이 아니라 **아키텍처 필연**이다.

## 사용자 철학과의 정합성

| 계층 | 정의 | 코드 매핑 | 정합 |
|---|---|---|---|
| T1 주요한 사실 — *항상 주입* | (코드 어디에도 명시 없음) | ❌ |
| T2 구체적 정보 — *markdown LTM 저장* | `memory/<category>/*.md`, archivers | ✅ |
| T3 탐색 능력 — *환경 탐색 도구* | `memory_search`, `memory_read` 등 9 + 진단 툴 | ⚠️ 회수율 낮음(다국어/자연어 매칭 실패) |
| T4 추론 | system prompt + LLM | ✅ |

T1의 부재가 본 사례의 직접 원인이다. 그리고 T1의 부재로 T3에 모든 부담이 가는데 T3의 회수율이 낮아 보완되지 못한다. 결국 사용자가 보기에 “저장만 잘하고 기억은 못 하는 시스템”이 된다.

## 핵심 결함 5선

### F1. 검색이 잡지 못하면 인사이트는 시스템 프롬프트에 못 들어간다 — 치명
- 위치: `geny-executor/src/geny_executor/memory/retriever.py` (6계층 전체) + `Geny/backend/service/memory/long_term.py:407-451`(키워드 라인)
- 본질: 회수 경로 6단 모두 어휘 일치 / 의미 거리 / slim_mode / 외부 키 / curated 매니저 등 *조건부* 작동.
- 결과: 한 번이라도 깔때기를 못 통과하면 system prompt에서 메모리 섹션이 통째로 사라진다.

### F2. 인사이트가 “주요한 사실”로 승격되지 않는다 — 치명
- 위치: `geny-executor/src/geny_executor/memory/strategy.py:435-446` `_save_insights` + `auto_promote`
- 사실 관계: critical/high 인사이트는 `CuratedKnowledgeManager`로 복제되지만, **항상 주입되는 자리(MEMORY.md, 또는 Persona/Memory 블록)에는 들어가지 않는다.**
- 즉 importance가 어느 값이든 회수는 같은 깔때기를 통과해야 한다.

### F3. 시스템 프롬프트가 능동 탐색을 명령하지 않는다 — 높음
- 위치: `geny-executor/src/geny_executor/memory/presets.py:320-352`(`_DEFAULT_WORKER_PROMPT`, `_DEFAULT_VTUBER_PROMPT`)
- 결과: 메모리 도구가 있어도 LLM이 부를 동기가 약하다. 메타 정보(“이 사용자에 대한 무엇이 저장되어 있을 수 있다”)도 안 보인다.

### F4. 저장과 회수의 자동화 비대칭 — 높음
- 저장은 자동(record_message → JSONL + ConversationArchiver + DM/Daily/Index 자동 갱신).
- 회수는 수동(검색이 우연히 잡거나, 에이전트가 능동적으로 툴을 부르거나).
- 결과: 사용자 UI에는 잘 쌓이는데 에이전트 응답엔 안 나온다.

### F5. 키워드 검색이 다국어를 못 잡는다 — 높음
- 위치: `Geny/backend/service/memory/long_term.py:409`
  ```python
  keywords = [w for w in query_lower.split() if len(w) >= 2]
  ```
- 사실 관계: 단순 토큰 분리 + `count`. 한국어 질의에 영어 인사이트는 0건.
- 벡터 fallback도 `manager.search()` 경로엔 없다(`manager.py:991-1022`).

| ID | 강도 | 내용 |

| O1 | 중 | `slim_mode` 기본 OFF — Memory v2 PR 9/10이 기획한 “목차 인젝션 + 툴 회수” 흐름이 운영에 들어가지 않음 |
| O2 | 중 | `MEMORY.md`로 자동 합쳐지는 경로 없음 — 사용자가 직접 글을 써넣지 않으면 영구 빈 파일 |

| O6 | 약 | 이전 감사 GP1(`Geny/.../memory_provider/registry.py` 들여쓰기 버그)이 새 Provider 경로 자체를 무력화 — 본 회수 실패와 별개의 리스크 |

## 무엇이 잘 되어있는가

- **저장 측의 견고함.** STM JSONL append + RLock + 2000줄 cap, ConversationArchiver의 leaf-SoT 17키 frontmatter, MemoryIndexManager의 `_index.json`과 `_vault_map.json` 분리. 디스크 측은 신뢰 가능하다.
- **인사이트 추출 프롬프트의 엄격성.** `_build_reflection_prompt`(strategy.py:306-369)는 행동/일반론/턴 전술을 명시적으로 거부하고 reserved category를 host측에서 강제 변환한다. 이는 “저장 가치 있는 사실만 박는다”는 좋은 디자인이다.
- **툴 카탈로그의 풍부함.** `memory_search` / `memory_read` / `memory_list` / `memory_distill` / `memory_with` / `memory_event` 등 진단·운영용 툴이 충분하다.

저장과 도구는 잘 깔려있고, 빠진 것은 **둘을 잇는 “주요한 사실 = 항상 주입” 계층**이다.

## 영향 분석

본 결함은 다음을 사용자가 직접 체감하게 만든다.

1. **사용자 호칭/관계 망각** — 본 사례. 신뢰 손상이 가장 크다.
2. **반복 질문** — 이전에 답한 사실을 재차 물어봐야 답을 끌어낼 수 있다.
3. **장기 프로젝트 컨텍스트 분실** — projects/ 노트가 검색 일치할 때만 잡힌다.
4. **다중 세션 협업 약화** — 큐레이티드 노트를 가로지르는 회수가 약하다.
5. **에이전트 페르소나 이탈** — “나는 이런 캐릭터다”를 박아둘 자리도 동일 결함을 공유한다.

## 권고 우선순위

1. **T1(주요한 사실) 계층을 코드에 명시한다.** `memory/critical/` 디렉토리 또는 `MEMORY.md`로의 자동 합성 경로 둘 중 하나.
2. retriever가 매 턴 T1 전체를 budget의 일정 비율(권장 30%) 안에서 **쿼리와 무관하게** 주입하도록 강제한다.
3. `auto_promote` 시 큐레이티드뿐 아니라 **T1 디렉토리에도 동시에 박는다**(또는 `MEMORY.md`로 append).
4. 시스템 프롬프트에 “이 사용자에 대해 알고 있는 사실은 다음 디렉토리에 모여 있으니 필요시 `memory_search` / `memory_read`를 적극 사용하라”는 메타 지침을 추가한다.
5. 키워드 검색에 vector fallback을 합치고, 다국어 토크나이저(혹은 normalize)를 적용한다.
